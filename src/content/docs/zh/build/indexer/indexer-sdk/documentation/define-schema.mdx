建立索引的第一步是选择数据库，并为要存储的数据定义架构。

## 架构注意事项

设计索引器数据架构时，请考虑以下内容：

- 可定制性：架构是 dApp 访问为特定合约或应用定制数据的接口。确保架构已针对 dApp 的独特需求进行定制。
- 查询优化：设计良好的架构可实现更高效的数据检索，支持聚合、复杂筛选和表联接等高级操作。
- 性能提升：架构设计可以显著提高 dApp 的性能。借助 Indexer，单个索引器查询通常可替代多次全节点查询。

## Aptos 核心处理器

[Indexer API](/zh/build/indexer/indexer-api) 公开的所有数据最初都由自定义处理器建立索引。每个核心处理器都会索引特定类型的数据。您可以浏览[完整的处理器列表](https://github.com/aptos-labs/aptos-indexer-processors-v2/blob/main/processor/src/db/schema.rs)。

Aptos 核心处理器和[快速入门指南](/zh/build/indexer/indexer-sdk/quickstart)均使用 [PostgreSQL](https://www.postgresql.org/) 作为数据库，并使用 [Diesel](https://diesel.rs/) 作为 ORM。如果您也想使用 PostgreSQL 和 Diesel，可以遵循 [PostgreSQL 安装](/zh/build/indexer/indexer-sdk/quickstart#postgresql-安装)中的说明。

您可以自由选择任何数据库和 ORM。常用替代方案包括 [SeaORM](https://www.sea-ql.org/SeaORM/) 和 [SQLx](https://github.com/launchbadge/sqlx)。如需指导，请参阅上面链接的教程。
