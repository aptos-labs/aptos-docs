赞助交易允许一个账户（费用支付者）为另一个账户（发送者）提交的交易支付 Gas 费。这对于抽象 Gas 成本以改善用户引导体验非常有用。

## 流程

要执行赞助交易，您必须构建 payload，使用发送者和费用支付者对其进行签名，然后提交。

1. **指定费用支付者构建：** 使用 `buildFeePayer` 而不是标准的 `build` 方法。
2. **发送者签名：** 发送者对交易内容进行身份验证。
3. **费用支付者签名：** 费用支付者签名以授权支付 Gas 费用。
4. **提交：** 将两个身份验证器提供给 `submit`。

所有方法均返回 `AptosResult<T>`，您可以使用 `when` 表达式或扩展函数来处理它。

```kotlin
// 使用简写语法构建负载
val payload = TransactionPayload.entryFunctionOf(
  "0x1::aptos_account::transfer",
  bob.accountAddress,
  1_000_000UL,
)

// 1. 指定付费者构建交易
val txn = aptos.transactions.buildFeePayer(
  sender = alice.accountAddress,
  payload = payload,
  feePayer = sponsor.accountAddress,
).getOrNull()!!

// 2. 发送方签名
val senderAuth = aptos.transactions.sign(signer = alice, transaction = txn).getOrNull()!!

// 3. 付费者签名
val feePayerAuth = aptos.transactions.sign(signer = sponsor, transaction = txn).getOrNull()!!

// 4. 使用两个验证器提交交易
val pending = aptos.transactions.submit(
  transaction = txn,
  senderAuthenticator = senderAuth,
  feePayerAuthenticator = feePayerAuth,
).getOrNull()!!

// 5. 等待确认
val confirmed = aptos.transactions.waitForTransaction(pending)
```

<Aside>
  如果您正在使用外部的费用支付者服务（例如 Gas Station），而您没有赞助者的私钥，您可以为外部服务构建一个请求：

  ```kotlin
  // Build with a zero-address placeholder (no feePayer specified)
  val txn = aptos.transactions.buildFeePayer(
    sender = alice.accountAddress,
    payload = payload,
  ).getOrNull()!!

  // Sender signs the transaction
  val senderAuth = aptos.transactions.sign(signer = alice, transaction = txn).getOrNull()!!

  // Create a request for an external Gas Station
  val request = aptos.transactions.externalFeePayerRequest(
    transaction = txn,
    senderAuthenticator = senderAuth,
  ).getOrNull()!!
  ```
</Aside>
