Aptos 节点是 Aptos 生态系统中跟踪 Aptos 区块链[状态](/zh/network/glossary#状态)的实体。客户端通过 Aptos 节点与区块链交互。节点有两种类型：

- [验证者节点](/zh/network/blockchain/validator-nodes)
- 全节点

每个 Aptos 节点由多个逻辑组件组成：

- [REST API 服务](/zh/network/glossary#rest-api-服务)
- [内存池](/zh/network/blockchain/validator-nodes#内存池)
- [执行](/zh/network/blockchain/validator-nodes#执行)
- [虚拟机](/zh/network/blockchain/validator-nodes#虚拟机-vm)
- [存储](/zh/network/blockchain/validator-nodes#存储)
- [状态同步器](/zh/network/blockchain/validator-nodes#状态同步器)

[Aptos-core](/zh/network/glossary#aptos-core) 软件可配置为运行验证者节点或全节点。

## 概览

任何人都可以运行全节点。全节点通过重新执行 Aptos 区块链历史中的所有交易，或重放每笔交易的输出，来验证区块链历史。全节点会与上游参与者（如其他全节点或验证者节点）同步，从而复制区块链的完整状态。为验证区块链状态，全节点会接收交易集合，以及由验证者签名的账本[累加器根哈希](/zh/network/glossary#accumulator-root-hash)。此外，全节点接受 Aptos 客户端提交的交易，并将其直接或间接转发给验证者节点。全节点与验证者使用相同的代码，但全节点不参与共识。

根据全节点的上游节点，全节点可称为验证者全节点或公共全节点：

- **验证者全节点**直接从验证者节点进行状态同步。
- **公共全节点**从其他全节点进行状态同步。

它们的功能没有区别，区别仅在于上游节点是验证者还是其他全节点。请在[这里](/zh/network/blockchain/node-networks-sync)阅读网络拓扑详情。

第三方区块链浏览器、钱包、交易所和 dApp 可能运行本地全节点，以：

- 利用 REST 接口进行区块链交互。
- 获取 Aptos 账本的一致视图。
- 避免读取流量的速率限制。
- 对历史数据运行自定义分析。
- 接收特定链上事件的通知。
